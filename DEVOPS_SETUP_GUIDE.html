URL Shortener: Jenkins, Kubernetes, Prometheus and Grafana

A Windows/Docker Desktop step-by-step runbook for this repository.

What is already in this project?

The repository already contains jenkins/Jenkinsfile, Kubernetes manifests in k8s/, Docker Compose services for PostgreSQL, the API, Prometheus and Grafana, Prometheus configuration in monitoring/prometheus.yml, and a provisioned Grafana dashboard in monitoring/grafana/dashboard.json.

This guide explains how to configure and run them. Jenkins and Kubernetes are tools that must still be installed and configured on your computer. The easiest monitoring demonstration uses Docker Compose for Prometheus and Grafana while Kubernetes runs the application.

2. Install prerequisites

Install these on the machine used for the demonstration:

  • Git, Node.js 20 or newer, and npm
  • Docker Desktop, with Docker Engine running
  • Docker Desktop Kubernetes enabled, or Minikube/kind
  • kubectl available in PowerShell
  • Jenkins running on a Linux/Docker agent for the supplied Jenkinsfile
  • A Docker Hub account and an empty image repository named url-shortener

Check the local tools:

git --version
node --version
npm --version
docker version
kubectl version --client
kubectl get nodes
The supplied Jenkinsfile uses Linux shell steps such as sh, npm ci, docker and kubectl. Use a Jenkins Linux agent or a Jenkins agent running Docker/Linux. Do not run this Jenkinsfile on a Windows-only agent without adapting every sh step to PowerShell.

3. Verify the project locally first

Run these commands from the repository root, for example D:\url_shortner:

git clone https://github.com/CoyoteClear340/URL_Shortner-DevOps_CIE-.git
cd URL_Shortner-DevOps_CIE-
npm ci
npm test
npm run lint

Start the complete local stack. This starts PostgreSQL, the API, Prometheus and Grafana:

docker compose up --build -d
docker compose ps
docker compose logs app

Verify the API:

Invoke-WebRequest http://localhost:3000/ -UseBasicParsing
Invoke-WebRequest http://localhost:3000/health -UseBasicParsing
Invoke-WebRequest http://localhost:3000/metrics -UseBasicParsing

Open these URLs:

http://localhost:3001/Grafana; default login is admin/admin

4. Build and publish the Docker image

Why: Jenkins cannot deploy source code directly. It builds one immutable image, pushes that image to Docker Hub, and Kubernetes runs the same image.

docker build -t YOUR_DOCKERHUB_USERNAME/url-shortener:local .
docker images YOUR_DOCKERHUB_USERNAME/url-shortener
docker run --rm -p 3000:3000 YOUR_DOCKERHUB_USERNAME/url-shortener:local

In another PowerShell window:

Invoke-WebRequest http://localhost:3000/health -UseBasicParsing

Publish a test tag:

docker login
docker tag YOUR_DOCKERHUB_USERNAME/url-shortener:local YOUR_DOCKERHUB_USERNAME/url-shortener:v1
docker push YOUR_DOCKERHUB_USERNAME/url-shortener:v1

5. Create the Kubernetes deployment

Why: Kubernetes keeps the API running, provides a stable Service address, performs health checks, and can scale two pods to four pods.

5.1 Create a registry pull secret and application secret

For a public Docker Hub repository, a registry secret is optional. The database secret is required by the deployment. Create it without committing credentials to Git:

kubectl apply -f k8s/namespace.yaml
kubectl -n url-shortener create secret generic postgres-secret `
  --from-literal=POSTGRES_PASSWORD=urlshortener --dry-run=client -o yaml | kubectl apply -f -
kubectl -n url-shortener create secret generic url-shortener-secret `
  --from-literal=DATABASE_URL=postgresql://urlshortener:urlshortener@postgres:5432/urlshortener `
  --dry-run=client -o yaml | kubectl apply -f -

For a private Docker Hub repository, create a pull secret:

kubectl -n url-shortener create secret docker-registry dockerhub-registry `
  --docker-server=https://index.docker.io/v1/ `
  --docker-username=YOUR_DOCKERHUB_USERNAME `
  --docker-password=YOUR_DOCKERHUB_ACCESS_TOKEN `
  --docker-email=YOUR_EMAIL
Use a Docker Hub access token instead of your Docker Hub password. Never put real passwords, tokens or secret.yaml files in Git.

5.2 Apply PostgreSQL and the API

kubectl apply -f k8s/configmap.yaml
kubectl apply -f k8s/postgres.yaml
kubectl apply -f k8s/deployment.yaml
kubectl apply -f k8s/service.yaml
kubectl get all -n url-shortener
kubectl get pods -n url-shortener -w

Check details and logs:

kubectl describe deployment url-shortener -n url-shortener
kubectl logs deployment/url-shortener -n url-shortener
kubectl get service url-shortener -n url-shortener

Access the Service from the laptop:

kubectl port-forward service/url-shortener 3000:3000 -n url-shortener

Then verify http://localhost:3000/health. The deployment starts with 2 replicas. Demonstrate scaling:

kubectl scale deployment url-shortener --replicas=4 -n url-shortener
kubectl get pods -n url-shortener

5.3 Deploy the exact Jenkins image manually

Jenkins uses tags such as build-17. Test the same deployment behavior manually:

kubectl -n url-shortener set image deployment/url-shortener `
  url-shortener=YOUR_DOCKERHUB_USERNAME/url-shortener:v1
kubectl rollout status deployment/url-shortener -n url-shortener

If the image is private, add imagePullSecrets to the pod template in k8s/deployment.yaml:

spec:
  imagePullSecrets:
    - name: dockerhub-registry

6. Create the Jenkins pipeline

Why: Jenkins makes every change follow the same checkout, test, image-build, image-push and deployment process. This prevents a manually tested image from being different from the image deployed to Kubernetes.

6.1 Start Jenkins

Use an existing Jenkins server, or run one locally. A production-like Jenkins setup needs a Linux agent with Docker CLI, access to the Docker daemon, Node.js/npm, Git, kubectl and a Kubernetes kubeconfig credential.

In Jenkins, install these plugins from Manage Jenkins → Plugins:

  • Pipeline
  • Git
  • Credentials Binding
  • Docker Pipeline
  • Kubernetes CLI

6.2 Add Jenkins credentials

Credential IDTypeValueUsed by
dockerhub-credentialsUsername with passwordDocker Hub username and access tokenDocker Push stage
kubernetes-configSecret file or kubeconfig credential supported by the Kubernetes CLI pluginAccess to the target clusterKubernetes Deploy stage

Never write either value directly in jenkins/Jenkinsfile.

6.3 Create the Pipeline job

  1. Open Jenkins and select New Item.
  2. Name it url-shortener-pipeline.
  3. Select Pipeline and press OK.
  4. Under Pipeline → Definition, select Pipeline script from SCM.
  5. SCM: Git; enter the GitHub repository URL.
  6. Select the branch, normally main.
  7. Script path: jenkins/Jenkinsfile.
  8. Save, then select Build with Parameters.

6.4 Supply pipeline parameters

DOCKER_IMAGE=YOUR_DOCKERHUB_USERNAME/url-shortener
KUBE_NAMESPACE=url-shortener

The pipeline stages are already present in jenkins/Jenkinsfile:

Checkout
Install Dependencies
Test
Docker Build
Docker Push
Kubernetes Deploy

Click Build Now. Open the build and inspect Console Output. A successful build should show tests passing, an image tag such as YOUR_DOCKERHUB_USERNAME/url-shortener:build-1, a Docker push, and a successful Kubernetes rollout.

6.5 Optional GitHub webhook

For a live push-to-build demonstration, configure a reachable Jenkins URL and a GitHub webhook pointing to JENKINS_URL/github-webhook/. Select the GitHub trigger in the Jenkins job. If Jenkins is only on localhost, use manual Build with Parameters; localhost cannot receive a GitHub webhook from the public internet.

7. Create Prometheus and Grafana monitoring

Why: the API exposes counters and a latency histogram at /metrics. Prometheus scrapes those metrics. Grafana runs PromQL queries against Prometheus and displays request rate, errors, latency and healthy instances.

7.1 Run monitoring with Docker Compose (recommended for this project)

docker compose up --build -d
docker compose ps
docker compose logs prometheus
docker compose logs grafana

The project configuration makes Prometheus scrape app:3000/metrics using monitoring/prometheus.yml. Grafana uses the provisioned datasource http://prometheus:9090 and imports the dashboard automatically.

In Prometheus, open Status → Targets. The url-shortener target must be UP. Test queries under Graph:

http_requests_total
sum(rate(http_requests_total[1m]))
sum(rate(http_errors_total[1m]))
histogram_quantile(0.95, sum(rate(http_request_duration_seconds_bucket[5m])) by (le))
count(up{job="url-shortener"} == 1)

7.2 Open and use Grafana

  1. Open http://localhost:3001.
  2. Sign in with admin/admin if prompted.
  3. Open the dashboard named URL Shortener - Full Observability.
  4. Confirm the four panels: Request Rate, Error Rate, Request Latency (p95), and Healthy Application Instances.

Generate normal traffic:

.\scripts\generate-traffic.ps1 -Count 100

Every tenth request is an intentional unknown short-code request. It produces a controlled 404 and raises http_errors_total; PowerShell now handles this expected response without printing noisy failures. Refresh the Grafana time range if necessary.

7.3 Optional: scrape Kubernetes pods with Prometheus

The repository also contains k8s/prometheus-config.yaml with Kubernetes pod discovery and the required annotations on the API deployment. This is a configuration ConfigMap, not a complete Prometheus installation. A Kubernetes Prometheus server also needs a Deployment, Service and RBAC permissions to discover pods. For the simplest reliable CIE demo, run the already-complete Compose Prometheus/Grafana stack and run the application in Kubernetes.

8. Suggested 8–10 minute live demonstration

  1. Git: create feature/shorten-api, commit, push, open a pull request and merge.
  2. Jenkins: start Build with Parameters and show Checkout, Test, Docker Build, Docker Push and Kubernetes Deploy.
  3. Docker: show the Dockerfile, image tag and Docker Hub repository.
  4. Kubernetes: run kubectl get pods -n url-shortener, show 2 pods, then scale to 4.
  5. Prometheus: open /targets and show the target UP; run sum(rate(http_requests_total[1m])).
  6. Grafana: open the dashboard and run the traffic script; explain rate, errors and p95 latency.
  7. Troubleshooting: temporarily deploy a wrong image tag, show ImagePullBackOff, use kubectl describe pod, restore the correct image and verify Running.

9. Troubleshooting

ProblemCommands and fix
Root URL returns 404Restart the API after pulling the latest code. Use /health for the health endpoint.
Compose app is unhealthydocker compose logs postgres, then docker compose logs app. Confirm PostgreSQL is healthy and restart with docker compose up --build -d.
Prometheus target is DOWNCheck docker compose ps, docker compose logs prometheus, and confirm the target is app:3000, not localhost:3000.
Grafana has no dataConfirm Prometheus target is UP, open Grafana datasource settings, and run the Prometheus query directly first.
Pod is ImagePullBackOffkubectl describe pod POD_NAME -n url-shortener. Correct the image name/tag or create the private registry pull secret.
Jenkins cannot run dockerInstall Docker CLI on the agent and give the agent access to the Docker daemon. Verify with docker version as the Jenkins user.
Jenkins cannot run kubectlInstall kubectl on the agent and verify the kubernetes-config credential points to the intended cluster.
Jenkins webhook does not triggerUse manual Build with Parameters for localhost Jenkins, or expose Jenkins through a secure reachable URL and configure the GitHub webhook.

10. Stop and clean up

docker compose down
kubectl delete namespace url-shortener

The Kubernetes delete command removes the demonstration namespace and its resources. Use it only when you want to clean up this project.
